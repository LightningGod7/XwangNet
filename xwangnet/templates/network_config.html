External IP Binding Configuration
What is External IP Binding?

When you disable network isolation, XwangNet can bind your edge device (e.g., router honeypot) directly to a unique IP address on your local network. This makes the device appear as a physical device on the network, accessible via LAN and optionally exposed to the internet.

How it Works
  • Existing Interface: Bind to an IP address that's already configured on the server (e.g., 192.168.7.118)
  • New Interface: Create a new macvlan interface and lease a new IP from the router (e.g., 192.168.7.220)
  • All ports (1-65535) from the edge device are forwarded to the selected IP
  • Traffic is monitored by Suricata IDS to capture attack telemetry
Configuration Options

Best for: Quick setup without creating new network interfaces
Requirement: Must have an available IP that isn't used by critical services
Note: All ports on that IP will be forwarded to the edge device

Best for: Clean deployment with dedicated IP
Requirement: Router must have available DHCP leases
Automatic: XwangNet creates a macvlan interface and requests IP via DHCP
Preferred Range: 192.168.7.220-254 (configurable in router)

Best for: Specific IP requirements or DHCP exhaustion
Requirement: IP must not be in DHCP range or reserved in router
Manual: You specify the exact IP to assign
⚠️ Critical Warnings
DANGER: Using Existing Server IP

If you select an existing interface with the server's IP address (e.g., 192.168.7.118):

  • ❌ SSH connection will be DISCONNECTED immediately
  • ❌ Web server (port 8000) will become INACCESSIBLE
  • ❌ You will LOSE REMOTE ACCESS to the server
  • ❌ All ports (1-65535) will be forwarded to the edge device

✅ SOLUTION: Always use "Create New Interface" option to avoid this issue. The system will now block selection of server IPs, but be aware of the risk.

Other Important Warnings
  • Network Access: Edge devices will be fully accessible from your LAN. Ensure proper security measures
  • Internet Exposure: If you port-forward on your router, the device will be exposed to the internet (intended for honeypot use)
  • Testing Required: Always use the "Test Configuration" button before deployment to validate settings
  • Edge Device Required: You must designate an edge device on the previous page for external IP binding
Use Case: Honeypot Deployment

This configuration is designed for deploying IoT honeypots that are:

  • Detectable on Shodan and other internet scanners
  • Accessible to attackers for baiting and telemetry collection
  • Monitored by Suricata IDS for network-level attack detection
  • Running with OS-level telemetry via strace
